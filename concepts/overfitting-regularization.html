Overfitting & Regularization

The single most common way ML projects fail isn't a bad algorithm — it's a model that memorized its homework instead of learning the subject.

01 The plain-English version

Overfitting happens when a model learns the training data too well — including its noise and quirks — so it performs beautifully on data it's already seen but poorly on new data.

Regularization is a family of techniques that deliberately discourage a model from fitting the training data too perfectly, trading a bit of training accuracy for much better real-world performance.

02 The formal version

Overfitting corresponds to low bias but high variance — the model's predictions vary wildly depending on which specific training set it saw. The opposite failure, underfitting, is high bias: the model is too simple to capture the real pattern at all. The goal is the sweet spot in the bias-variance tradeoff.

Common regularization techniques: L1/L2 regularization adds a penalty term to the loss function proportional to the size of the model's weights, discouraging overly large, finely-tuned coefficients. Dropout (in neural networks) randomly disables neurons during training so the network can't over-rely on any single path. Early stopping halts training once performance on a held-out validation set stops improving, even if training accuracy is still climbing.

03 The flow

As model complexity increases, training accuracy keeps climbing — but real-world accuracy peaks and then falls. Regularization aims to stop at the peak.

04 Worked example

Spotting overfitting from the numbers

A model reaches 99.8% accuracy on its training set but only 71% on its validation set. That 28-point gap is the signature of overfitting — the model has essentially memorized answers rather than learning generalizable patterns. Adding L2 regularization or reducing tree depth might bring training accuracy down to 91% but push validation accuracy up to 88%, a model that's genuinely more useful despite "performing worse" on paper.

05 Where this shows up

Real-world use

Every serious ML pipeline includes a held-out validation set specifically to catch this — it's why you'll see terms like "validation loss" tracked separately from "training loss" in any real training run, and why a model's reported training accuracy alone tells you almost nothing about how it'll perform in production.

06 Common misconceptions

✕

Higher training accuracy means a better model. Past a certain point, higher training accuracy is a red flag for overfitting, not a sign of quality.

✕

Regularization is only needed for complex models like deep neural networks. Even simple linear regression overfits with too many features relative to data points — regularization applies across nearly all of ML.

✓

Correct framing: always judge a model by its performance on data it hasn't seen — training performance is a diagnostic tool, not a scoreboard.
