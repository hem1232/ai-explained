Tokenization & Embeddings

Neural networks only understand numbers. Before a model can do anything with language, every word has to be converted into a list of numbers that somehow captures what it means.

01 The plain-English version

Tokenization is the process of splitting text into smaller pieces — usually not whole words, but common sub-word chunks — so the model has a manageable, fixed vocabulary to work with, even for words it's never seen before.

An embedding is a learned list of numbers (a vector) assigned to each token, positioned in a high-dimensional space such that similar meanings end up near each other — "king" and "queen" land close together, while "king" and "bicycle" land far apart.

02 The formal version

Most modern models use subword tokenization algorithms like Byte-Pair Encoding (BPE) or SentencePiece, which build a vocabulary of common character sequences by iteratively merging the most frequent adjacent pairs in a training corpus — this lets rare or unseen words be represented as a combination of familiar pieces ("unbelievably" → "un" + "believ" + "ably") rather than failing outright.

Each token ID indexes into an embedding matrix — a learned table of vectors, typically hundreds to thousands of dimensions wide — that's trained jointly with the rest of the model. The geometric relationships between these vectors end up encoding meaning: a famous example is that the vector arithmetic king − man + woman lands close to the vector for queen.

03 The flow

Text is split into sub-word tokens, each token maps to an ID, and each ID looks up a learned vector that encodes meaning.

04 Worked example

Vector arithmetic on meaning

Real embedding vectors have hundreds of dimensions, but a simplified 2D version illustrates the idea: if king = [0.9, 0.2], man = [0.8, -0.1], and woman = [0.3, -0.1], then king − man + woman = [0.4, 0.2] — a point that lands close to the learned vector for queen, purely because the model, during training, arranged its embedding space so that the "royalty" direction and the "gender" direction became roughly separable dimensions.

05 Where this shows up

Real-world use

Embeddings extend far beyond individual model internals — they're the backbone of semantic search, recommendation systems, and RAG systems (which retrieve relevant text by comparing embedding similarity rather than exact keyword matches). This is why a search for "puppy training tips" can return a result titled "how to raise a well-behaved dog" with no words in common at all.

06 Common misconceptions

✕

Tokenization always splits on whole words. Subword tokenization deliberately breaks rare or long words into pieces — which is also why LLMs sometimes struggle with character-level tasks like counting letters in a word, since they don't see individual letters directly.

✕

Embeddings are hand-designed by engineers. They're learned automatically during training, purely from patterns of which words tend to appear in similar contexts — no one manually decides that "king" and "queen" should be close together.

✓

Correct framing: tokenization and embeddings are the translation layer between human language and the math a neural network can actually operate on — everything downstream depends on this translation being good.
