Data, Features & Labels

Before any algorithm matters, someone has to decide what the model actually sees. That choice shapes everything the model can possibly learn.

01 The plain-English version

A feature is a measurable piece of information about something — a house's square footage, a customer's age, a pixel's brightness. Models don't see "a house"; they see a list of numbers describing it.

A label is the answer you want the model to learn to predict — the actual sale price, whether the customer churned, what digit a handwritten image shows. In supervised learning, every training example pairs features with a label.

02 The formal version

A dataset is typically represented as a matrix where each row is an example and each column is a feature; for supervised learning, a separate vector holds the corresponding labels. Feature engineering is the process of selecting or transforming raw data into a form a model can use effectively — for instance, converting a timestamp into "day of week" if that pattern matters more than the raw time.

Data is usually split into a training set (used to fit the model), a validation set (used to tune choices like model complexity), and a test set (used once, at the end, to estimate real-world performance) — keeping these separate is what prevents a model's reported accuracy from being misleadingly optimistic.

03 The flow

Raw information becomes features; the thing you're trying to predict is the label; the dataset gets split so evaluation stays honest.

04 Worked example

Turning a house listing into training data

A real estate listing — "3-bed, 2-bath, 1,450 sqft, built 1998, downtown Austin, sold for $412,000" — becomes one training row: features [3, 2, 1450, 1998, location_score=0.82] and label 412000. Do this for 50,000 historical listings, split 70% training / 15% validation / 15% test, and you have a dataset a regression model can learn from.

05 Where this shows up

Real-world use

Feature quality is often the single biggest factor in a model's real-world performance — more than the choice of algorithm. Data teams at most companies spend far more time on cleaning, labeling, and engineering features than on tuning models, which is why "data-centric AI" has become as important a discipline as model architecture itself.

06 Common misconceptions

✕

More data always beats better features. Garbage features with lots of data still produce a poor model — quality and relevance usually matter more than raw volume.

✕

Labels are always objective ground truth. Labels are often produced by human annotators, which means they can carry the same biases and inconsistencies as any human judgment.

✓

Correct framing: a model can only be as good as the features and labels it's trained on — most of the real "intelligence" work in a project happens before training even starts.
