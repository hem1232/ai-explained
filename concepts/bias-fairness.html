Bias & Fairness

A model doesn't need to be programmed with prejudice to produce unfair outcomes — it only needs to learn patterns from data that already reflects historical inequities, which is nearly all real-world data.

01 The plain-English version

AI bias happens when a model's predictions systematically disadvantage certain groups — not because anyone intended it, but because the training data reflected existing societal patterns, and the model faithfully learned those patterns as if they were the correct rule to follow.

"Fairness" turns out to be genuinely difficult to define precisely — there are several mathematically valid, well-studied definitions of fairness, and a model can satisfy some of them while violating others simultaneously, which is a real mathematical fact, not just a matter of unclear intentions.

02 The formal version

Bias can enter a pipeline at multiple points: historical bias (training data reflects real-world inequities, like historical hiring patterns), representation bias (some groups are underrepresented in training data), and measurement bias (a proxy label imperfectly represents what you actually want to measure — e.g. "arrests" as a proxy for "criminal behavior" conflates the two).

Common formal fairness definitions include demographic parity (positive prediction rates equal across groups), equalized odds (true and false positive rates equal across groups), and predictive parity (precision equal across groups) — a well-known impossibility result shows that except in special cases, a model can't simultaneously satisfy all of these at once when base rates differ between groups, which forces an explicit choice about which notion of fairness matters most for a given application.

03 The flow

Bias flows in through the data, gets encoded as a learned pattern, and shows up in predictions — auditing and mitigation have to intervene somewhere along this chain.

04 Worked example

A documented real-world case

A well-studied 2019 healthcare algorithm used projected healthcare costs as a proxy for patient need, to decide who should be enrolled in extra-care programs. Because less money had historically been spent on Black patients for the same level of underlying illness — often due to unequal healthcare access — the algorithm systematically underestimated how sick Black patients actually were, and recommended them for extra care less often than white patients with equivalent health needs. The model wasn't given race as an input at all; the bias came entirely through a flawed proxy for the outcome it was actually trying to predict.

05 Where this shows up

Real-world use

Fairness auditing is now a standard (and in some jurisdictions, legally required) step for high-stakes ML deployments — hiring algorithms, credit scoring, criminal risk assessment, and healthcare resource allocation are all areas where fairness metrics are actively measured, monitored, and regulated, and where bias incidents have driven real changes in industry and policy.

06 Common misconceptions

✕

Removing a sensitive attribute (like race) from the training data prevents bias. Correlated proxy variables (like zip code) often let a model reconstruct the removed information indirectly — this is well-documented and known as "fairness through unawareness," and it doesn't reliably work.

✕

There's one single, objectively correct definition of "fair." Multiple mathematically valid fairness definitions can conflict with each other in provable ways — choosing between them is a values-laden decision, not a purely technical one.

✓

Correct framing: fairness work requires explicitly deciding, for a given application, which kind of fairness matters most, measuring it directly, and treating that as an ongoing constraint on the system — not something you fix once and forget.
