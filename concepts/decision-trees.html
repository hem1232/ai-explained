Decision Trees & Random Forests

A decision tree is the ML model that looks most like human reasoning — a chain of yes/no questions. A random forest is what happens when you stop trusting just one chain of questions.

01 The plain-English version

A decision tree predicts by asking a series of yes/no questions about the data — "is income above $50k? Is debt ratio above 30%?" — branching further at each answer until it reaches a final prediction.

A random forest trains hundreds of slightly different decision trees, each seeing a random subset of the data and features, then lets them vote — averaging out any single tree's blind spots.

02 The formal version

At each node, a decision tree chooses the feature and threshold split that best separates the data — commonly measured by Gini impurity or information gain — and repeats recursively on each resulting subset until a stopping condition (max depth, minimum samples per leaf) is reached.

Random forests are an ensemble method: they reduce variance by combining many high-variance, low-bias trees via bagging (bootstrap aggregating) — training each tree on a random sample of the data drawn with replacement — plus random feature selection at each split, which decorrelates the trees so their errors don't all point the same direction.

03 The flow

A single tree asks a chain of questions down to a leaf; a forest runs many different trees and combines their votes.

04 Worked example

One tree's decision path

For a loan applicant with income $65k and debt ratio 25%: the tree first checks income > $50k? → yes, go right. Then debt_ratio > 30%? → no, go left. That path lands on a leaf that says "approve" because 92% of training applicants who followed this exact path repaid their loan. A random forest would run this applicant through 200 such trees, each built slightly differently, and approve only if a strong majority agree.

05 Where this shows up

Real-world use

Random forests and their close relative, gradient-boosted trees (like XGBoost), are the dominant approach for structured/tabular data in industry — fraud detection, churn prediction, and most Kaggle-competition-winning models on non-image, non-text data use tree ensembles rather than neural networks.

06 Common misconceptions

✕

A single decision tree is usually accurate enough to deploy. Individual trees overfit easily and are highly sensitive to small changes in training data — ensembles exist specifically to fix this instability.

✕

Random forests can't be interpreted, like neural networks. They're actually more interpretable than deep learning — feature importance scores tell you which inputs the forest relies on most, even if you can't trace one exact decision path.

✓

Correct framing: use a single tree when you need a fully transparent rule set; use a forest (or boosted trees) when you need accuracy on tabular data and can tolerate slightly less transparency.
